1. 项目概述

本项目 不是从源码编译 ImmortalWrt，而是利用官方提供的 ImageBuilder Docker 镜像，在 GitHub Actions 中自动化打包固件。

ImageBuilder 的工作方式是：给定一个包列表，它从预编译的软件仓库中下载并组装成完整的固件镜像（img / ISO）。

核心特点：

  • 通过 Docker 容器运行 ImageBuilder，无需本地搭建编译环境
  • 支持 workflow_dispatch 手动触发，在 GitHub Actions UI 上选择参数
  • 支持集成第三方软件包（ipk / apk）
  • ISO 工作流额外封装为可引导的 Debian Live 安装器

4.3 ISO 工作流执行流程

ISO 工作流分为 两个 Job：

Job 1: build_immortalwrt — 构建固件 img

Checkout 代码 → 设置 build25.sh 可执行权限 → 校验 PPPoE 输入 → 若勾选 enable_store 则追加 luci-app-store → Docker 运行 ImageBuilder 容器 → 复制 img.gz 到根目录 → 上传为 artifact

Job 2: build_installer_iso — 封装为 ISO

下载 Job 1 产出的 firmware-img → 克隆 wukongdaily/img-installer → 执行 autobuild.sh 将 img.gz 封装为 ISO → 上传 ISO 到 GitHub Release

4.4 Docker 容器挂载详情（25.12.x ISO）

docker run --rm -i --user root \
  -v bin/            → /home/build/immortalwrt/bin          # 产出目录
  -v files/          → /home/build/immortalwrt/files         # 首次启动脚本
  -v custom/         → /home/build/immortalwrt/files/etc/config  # 自定义路由器IP
  -v x86-64/imm25.config → /home/build/immortalwrt/.config  # ImageBuilder 配置
  -v shell/          → /home/build/immortalwrt/shell         # 自定义包脚本
  -v x86-64/build25.sh  → /home/build/immortalwrt/build.sh  # 构建入口脚本
  -e PROFILE / INCLUDE_DOCKER / ENABLE_PPPOE / ...          # 环境变量
  immortalwrt/imagebuilder:x86-64-openwrt-${luci_version}

5.2 自定义包脚本的工作原理

以 apk-custom-packages.sh 为例，所有条目默认被注释，用户取消注释即可启用：

# 未启用（默认）
#CUSTOM_PACKAGES="$CUSTOM_PACKAGES luci-app-passwall2 luci-i18n-passwall2-zh-cn"

# 已启用（去掉行首 #）
CUSTOM_PACKAGES="$CUSTOM_PACKAGES luci-app-passwall2 luci-i18n-passwall2-zh-cn"

脚本通过 bash 变量拼接的方式，将所有启用的包名累积到 CUSTOM_PACKAGES 变量中，最终在 build25.sh 中合并到 PACKAGES 字符串传给 make image。

6. 如何启用第三方软件

6.1 方法一：编辑 shell/ 脚本（推荐）

步骤：

  1. Fork 本仓库到自己的 GitHub 账号
  2. 根据目标版本编辑对应的脚本：
    • 25.12.x → 编辑 shell/apk-custom-packages.sh
    • 24.10.x → 编辑 shell/custom-packages.sh
  3. 去掉想启用的包所在行的行首 #
  4. 提交修改到自己的仓库
  5. 在自己仓库的 Actions 页面手动触发工作流

6.2 方法二：通过工作流 UI 选项

部分高频操作已提取为工作流 UI 选项，无需修改代码：

  • enable_store：勾选后自动追加 luci-app-store 到自定义包脚本
  • include_docker：选择 yes 自动集成 Docker 管理插件
  • enable_pppoe：配置 PPPoE 拨号信息

原理：工作流 YAML 中通过 echo 'CUSTOM_PACKAGES=...' >> shell/xxx.sh 动态追加。

6.3 方法三：添加自定义包（高级）

如果需要的包不在脚本中，可以手动添加：

# 在 apk-custom-packages.sh 中添加新行
CUSTOM_PACKAGES="$CUSTOM_PACKAGES luci-app-xxx luci-i18n-xxx-zh-cn"

前提条件：

  • 该包必须存在于 ImmortalWrt 官方仓库中（仓库内插件）
  • 或者该包的 .apk/.ipk 文件存在于第三方仓库（wukongdaily/apk 或 wukongdaily/store）
  • 如果都不在，需要自行将包文件放入 extra-packages/ 目录结构中

8. 固件首次启动脚本

文件：files/etc/uci-defaults/99-custom.sh

固件首次启动时自动执行一次，完成以下配置：

#功能
1设置 WAN 防火墙入站规则为 ACCEPT（方便首次访问 WebUI）
2添加 time.android.com 域名映射（解决安卓 TV 联网问题）
3读取 PPPoE 配置（由 build.sh 动态生成）
4自动检测物理网口数量：单网口设 DHCP 模式，多网口设 WAN/LAN 分离
5特殊处理 radxa-e20c / nanopi-r5c 网口顺序
6多网口设备支持自定义管理 IP（从 custom_router_ip.txt 读取，默认 192.168.100.1）
7配置 PPPoE 拨号（若启用）
8设置 ttyd 和 SSH 允许所有网口访问
9修复 advancedplus 插件的 zsh 问题
10修复 quickfile 的 nginx 配置冲突
11配置 Docker 防火墙规则（扩大子网范围至 172.16.0.0/12）

9. 常见问题

Q: 构建失败提示找不到某个包怎么办？

A: 说明该包在 ImmortalWrt 官方仓库和第三方仓库中都不存在对应版本。请到 wukongdaily/apk（25.12.x）或 wukongdaily/store（24.10.x）确认包是否存在，然后注释掉该行。

Q: 固件太大或构建失败怎么办？

A: 硬路由闪存空间有限，减少启用的第三方包数量。可以增大 profile 参数（固件大小 MB），或减少同时启用的代理类插件。

Q: clashoo 和 nikki 可以同时启用吗？

A: 不可以，它们配置冲突。脚本中已标注此限制。

Q: ISO 安装器怎么用？

A: 将 ISO 写入 U 盘或挂载到虚拟机，引导进入 Debian Live 系统后输入命令 ddd 即可调出安装菜单，可选择目标硬盘进行安装。安装后的 OpenWrt 会有剩余磁盘空间。详见 wukongdaily/img-installer。

Q: 如何在 25.12.x 中使用 nekobox / momo / uninstall / netwizard？

A: 这些包目前在 apk-custom-packages.sh 中没有条目。需要：

  1. 确认 wukongdaily/apk 仓库中是否有对应 apk 包
  2. 如果有，在 apk-custom-packages.sh 中添加：
    CUSTOM_PACKAGES="$CUSTOM_PACKAGES luci-app-xxx"
  3. 如果没有，需要自行编译或寻找 apk 包放入 extra-packages/ 目录

Q: 24.10.x 和 25.12.x 的包能混用吗？

A: 不能。24.10.x 使用 ipk 格式（opkg），25.12.x 使用 apk 格式。包格式不同，脚本也不同，必须使用对应版本的脚本和仓库。
